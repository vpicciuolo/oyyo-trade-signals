# Customer user guide

## 1. Access OYYO Trade Signals

Visit [oyyosignals.trade](https://oyyosignals.trade), choose the appropriate product access and use a supported sign-in method. Verify your email when required and enable TOTP multi-factor authentication.

## 2. Start the demo or activate a licence

The 72-hour demo is limited to one per account and does not auto-convert. Paid features are activated from verified entitlement state, not from a browser redirect alone.

## 3. Enroll a device

Link an eligible installation to your account. Review and revoke devices in the account portal when a device is lost, sold or no longer used. Device enrollment does not give OYYO remote control of the device.

## 4. Build a research workspace

1. Add instruments to a watchlist.
2. Select the research horizon.
3. Review source identity and freshness.
4. Create a record with supporting and opposing evidence.
5. Review uncertainty, limitations, model version and provenance.
6. Save strategy notes and journal entries.

## 5. Ask OYYO

1. Open **Ask OYYO** from the OYYO intelligence button.
2. Choose a guided prompt or describe what you want in ordinary language.
3. Review the explanation and any proposed market, strategy, risk style or alert threshold.
4. Choose **Change** to continue the conversation or **Confirm** to let deterministic application code validate and save the proposal.

Ask OYYO runs locally with OYYO-SIGNAL-TINY-ALL 2026.11.1. The screen displays the active S1–S4 tier and local status. It cannot submit a real order.

## 6. Read an OYYO observation

Check all thirteen output fields. Pay special attention to horizon, freshness, uncertainty, opposing evidence, limitations, model identity and provenance. A market-state label is informational rather than a personal recommendation.

## 7. Configure alerts

Create rules from inputs available to the application. Confirm time zone, market session and freshness assumptions. Alerts can be delayed or missed and do not execute transactions.

## 8. Use paper trading

Review instrument, side, quantity, reference price and notional before recording a paper ticket. Use notional and daily-loss limits and the paper kill switch. Paper outcomes do not represent every live-market condition.

## 9. Review and learn

Connect research assumptions, paper activity and outcomes in the journal. Compare supporting and opposing evidence and note what changed between the original observation and later review.

## Account and support

Use the portal for profile, notifications, devices, invoices, downloads, support, export and deletion requests. Never send passwords, payment credentials, broker/exchange secrets, private keys or live access tokens to support.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Data looks stale | Provider timestamp, local clock, market session and connection |
| A model is unavailable | Device compatibility, application version and available memory |
| A feature is locked | Plan, demo expiry, entitlement and device enrollment |
| Login callback fails | System time, browser/app flow and callback expiry |
| Notifications do not arrive | OS permission, rule state and background restrictions |
| Billing access is delayed | Allow verified reconciliation; contact support without payment secrets |
